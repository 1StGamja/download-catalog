# Download Catalog 구현 계획서

> 작성일: 2026-10-11 / 상태: 설계 승인 후 구현 대기

## 1. 무엇을 만드나요?

Chrome으로 파일을 받으면 `Downloads` 폴더에 쌓이기만 하고, 나중에 "이거 언제, 어디서, 왜 받았더라?" 하고 기억이 나지 않습니다. 또 같은 파일을 다시 받으면 `파일(1).exe`처럼 이름만 바뀌어서 어떤 게 새 버전인지 알 수 없습니다.

**Download Catalog**는 윈도우 작업표시줄 오른쪽 아래(트레이)에 조용히 떠 있으면서 다음 일을 대신 해 주는 작은 프로그램입니다.

1. 새 파일이 다운로드되면 **자동으로 감지**합니다.
2. **어디서 받았는지**(URL), **언제 받았는지**를 기록합니다.
3. 이미 받은 파일인지, **새 버전인지** 판단합니다.
4. 작은 팝업을 띄워 **"왜 받았는지(목적)"를 한 줄로 적게** 합니다.
5. 나중에 **검색해서** 찾아볼 수 있습니다.

> 파일은 옮기거나 이름을 바꾸지 않습니다. `Downloads` 폴더에 그대로 두고 **기록(메모장 같은 카탈로그)만** 따로 남깁니다.

## 2. 사용하는 기술 (쉬운 설명)

| 기술 | 쉬운 설명 | 쓰는 곳 |
|---|---|---|
| Python 3.12 | 프로그램을 짜는 언어 (설치 완료) | 전체 |
| watchdog | 폴더에 새 파일이 생기면 알려 주는 감시 도구 | 폴더 감시 |
| SQLite (sqlite3) | 파일 하나로 된 간단한 데이터베이스. 별도 설치 없음 | 기록 저장 |
| tkinter | 파이썬에 기본 포함된 창(윈도우) 만들기 도구 | 팝업, 검색 창 |
| pystray + Pillow | 트레이 아이콘을 만드는 도구 | 트레이 |
| pytest | 코드가 맞게 동작하는지 자동으로 확인하는 도구 | 테스트 |

## 3. 프로그램 구조

프로그램을 **역할이 하나씩인 6개 부품(모듈)**으로 나눕니다. 부품 하나가 고장 나도 다른 부품은 영향을 덜 받고, 따로따로 테스트하기 쉽습니다.

```
Downloads 폴더
     │ 새 파일 생김
     ▼
[watcher] 감시 ──▶ [origin] 출처 조사 ──▶ [versioning] 중복·버전 판단
                                                │
                                                ▼
                         [popup] 목적 입력 ◀── [db] 기록 저장
                                                ▲
                         [tray] 트레이 메뉴 ─────┘ (카탈로그 열기, 일시정지, 종료)
```

### 부품별 역할

| 부품 | 하는 일 | 핵심 포인트 |
|---|---|---|
| **watcher** | Downloads 폴더를 지켜보다가 다운로드가 **끝난** 파일을 알려 줌 | Chrome은 받는 중에 `.crdownload` 임시 파일을 만듦. 이건 무시하고, 파일 크기가 잠시 변하지 않으면 "완료"로 판단 |
| **origin** | 파일의 출처(URL)를 알아냄 | ① 윈도우가 파일에 몰래 붙여 둔 `Zone.Identifier` 정보를 읽음 ② 없으면 Chrome 기록(History DB)에서 찾음. Chrome이 DB를 잠가 두므로 **복사본**을 만들어 읽음 |
| **versioning** | 같은 파일인지, 새 버전인지 판단 | 파일의 **SHA-256 해시**(파일 내용의 지문)를 계산해 비교. 지문이 같으면 같은 파일, 이름은 같은데 지문이 다르면 새 버전 |
| **db** | 모든 기록을 저장 | `%APPDATA%\DownloadCatalog\catalog.db` 파일 하나 |
| **popup** | 목적 태그와 메모를 입력받는 작은 창 | 건너뛰기 가능. 화면 모서리에 띄워 작업을 방해하지 않음 |
| **tray** | 트레이 아이콘과 메뉴 | 카탈로그 열기 / 일시정지 / 종료 |

## 4. 저장하는 정보 (DB 설계)

`downloads` 표 하나에 파일 한 건당 한 줄을 저장합니다.

| 항목 | 설명 | 예시 |
|---|---|---|
| id | 고유 번호 | 17 |
| file_name | 파일 이름 | `setup.exe` |
| file_path | 저장된 전체 경로 | `C:\Users\사용자\Downloads\setup.exe` |
| size | 파일 크기(바이트) | 5242880 |
| sha256 | 내용 지문 | `a3f1...` |
| downloaded_at | 받은 시각 | 2026-10-11 14:30 |
| source_url | 파일을 받은 주소 | `https://example.com/setup.exe` |
| referrer_url | 다운로드 버튼이 있던 페이지 | `https://example.com/download` |
| version | 같은 이름의 몇 번째 버전인지 | 2 |
| prev_id | 바로 이전 버전의 id | 9 |
| purpose | 목적 태그 | `업무`, `학습` |
| memo | 한 줄 메모 | "보고서 작성용 설치 프로그램" |

## 5. 핵심 동작 시나리오

### 시나리오 A: 처음 받는 파일
1. Chrome이 `report.pdf` 다운로드를 끝냄
2. watcher가 감지 → origin이 URL 조사 → versioning이 "처음 보는 파일"로 판단
3. DB에 기록 → 팝업이 뜸 → 목적을 입력하고 저장

### 시나리오 B: 같은 이름, 다른 내용 (새 버전)
1. `setup(1).exe`가 생김. 이름은 다르지만 versioning이 같은 프로그램 계열인지 파악
2. 지문이 다르면 **새 버전**. DB에 `version=2`, `prev_id=이전 기록`을 저장
3. 팝업에 "이전에 받은 `setup.exe`(2026-09-01)의 새 버전입니다"라고 안내

### 시나리오 C: 완전히 같은 파일을 다시 받음
1. 지문이 이전 기록과 똑같음
2. 팝업에 "이미 받은 파일입니다(2026-09-01)"라고 알려 주고, 새 기록으로 남길지 선택하게 함

## 6. 구현 순서 (작업 단계)

각 단계는 끝날 때마다 **직접 눈으로 확인할 수 있는 결과물**이 있도록 나눴습니다.

| 단계 | 할 일 | 확인 방법 |
|---|---|---|
| **0. 준비** | 프로젝트 폴더 구성, 가상환경(venv) 생성, 라이브러리 설치 | `pytest` 실행이 되는지 확인 |
| **1. db** | SQLite 표 생성, 저장·조회 함수 | pytest: 저장한 걸 다시 읽어 오는지 |
| **2. versioning** | SHA-256 계산, 중복·새 버전 판단 | pytest: 같은 내용, 다른 내용, 이름만 같은 경우 |
| **3. origin** | Zone.Identifier 읽기, Chrome History DB 조회 | pytest: 샘플 데이터로 파싱 확인. 실제 Chrome 다운로드로 수동 확인 |
| **4. watcher** | 폴더 감시, 임시 파일 무시, 완료 판단 | 임시 폴더에 파일을 떨어뜨려 감지되는지 확인 |
| **5. popup** | 목적·메모 입력창, 여러 파일이 연달아 올 때 순서대로 표시 | 직접 띄워 보기 |
| **6. tray + 연결** | 트레이 아이콘과 메뉴, 1~5번 부품 연결 | 실제로 Chrome에서 파일을 받아 전체 흐름 확인 |
| **7. 카탈로그 창** | 기록 목록, 검색(이름·URL·태그·메모), 파일 열기·폴더 열기 | 검색어를 넣어 결과 확인 |
| **8. 마무리** | 오류 처리 점검, 사용 설명서, 실행 방법 정리 | 처음부터 따라 해서 실행되는지 확인 |

## 8. 예상되는 어려움과 대비책

| 문제 | 대비책 |
|---|---|
| Chrome이 History DB를 잠가 두어 읽기 실패 | DB 파일을 임시 위치에 복사해서 읽음 |
| 출처 정보가 없는 파일 (직접 복사한 파일 등) | "알 수 없음"으로 기록하고 계속 진행 |
| 다운로드 중인 파일을 완료로 착각 | `.crdownload` 무시, 파일 크기가 몇 초간 같을 때만 완료로 판단 |
| 파일이 아직 잠겨 있어 지문 계산 실패 | 몇 번 다시 시도 |
| 팝업이 작업을 방해 | 화면 모서리에 띄우고, 건너뛰기 버튼 제공. 여러 개는 순서대로 하나씩 |
| 팝업이 실패해도 기록은 잃으면 안 됨 | 기록을 **먼저** 저장하고, 팝업은 그다음에 띄움 |

## 9. 이번 범위에 포함하지 않는 것

- 파일 자동 이동·이름 변경 (기록만 남기기로 결정)
- Chrome 확장 프로그램 (나중에 추가 검토)
- 다른 브라우저(Edge, Firefox) 지원
- 클라우드 동기화

## 10. 완료 기준

- 트레이에서 프로그램이 실행되고 종료할 수 있다.
- Chrome으로 파일을 받으면 팝업이 뜨고, 입력한 목적·메모가 저장된다.
- 출처 URL과 받은 시각이 자동으로 기록된다.
- 같은 파일을 다시 받으면 중복 또는 새 버전으로 알려 준다.
- 카탈로그 창에서 이름·URL·태그·메모로 검색할 수 있다.
- 자동 테스트가 모두 통과한다.
